## Ouvert : arbitrage attendu

- **Sender ID des SMS** : au nom du pro ou « Wiggy » (G4, explicitement « à trancher »).
- **Noms commerciaux et montants des 3 paliers** (§2 : à confirmer par les entretiens).
- **Places API** : A5 ② (« je suis à l'hôtel ») attend l'activation d'une seconde API Google,
  facturée à part. Le code est écrit et inerte tant que `GOOGLE_PLACES_API_KEY` est vide ; la
  cliente saisit alors l'adresse de son hôtel à la main, avec les communes desservies affichées.
- **Écran d'abonnement** : `requireCapability()` renvoie vers `/app/abonnement`, qui n'existe pas
  encore (G1). Un pro en offre 1 qui atteindrait « Ma tournée » par l'URL tomberait sur un 404.
  Le lien de navigation est masqué hors de l'offre qui l'inclut, ce qui referme le cas courant.

## Base de données des communes

La liste de communes (T8) suppose un référentiel : **base officielle INSEE / API Découpage
administratif** (code INSEE, nom, code postal, centroïde). Choix de la source et modalité
(import en base vs appel API à la volée) à faire au moment de construire l'écran B11,
signalé ici pour ne pas le découvrir en chemin.
